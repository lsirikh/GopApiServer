3. 불변성 원칙 6대 (명문화)

Workflow 6 agent 분석 결과로 명문화. 이 원칙들이 v4.8+의 모든 PUT/PATCH 설계 기준이 됨.

원칙 1. 영구 귀속 (Identity Permanence)
이벤트 발생 후 1:N invariant로 종속되는 FK는 PUT/PATCH로 변경 불가. *Replace 전용 스키마로 시그니처 분리하고 extra="forbid"로 422 회귀 차단.
예시: action_events.from_event_id (Phase 12-1 차단 완료 ✅)
원칙 2. 스냅샷 불가침 (Snapshot Immutability)
부모 삭제 후 추적성 보존용 스냅샷 필드는 사용자 입력으로 덮어쓸 수 없음. 입력 스키마 미노출 + extra="forbid" + 핸들러에서 강제 재계산.
예시: events.device_description (PATCH ✅ / PUT은 GAP)
원칙 3. 시스템 자동관리 (System-Managed Fields)
카운터/플래그/타임스탬프는 헬퍼 또는 시스템 default만 변경. 일반 *Update 경로 차단.
예시: action_reported (Phase 12-2 ✅), is_locked, failed_login_count, locked_at
원칙 4. Polymorphic Discriminator는 이미 안전 — type_device는 별개 (Sensor 예외)

실측 결과 SQLAlchemy Joined Table Inheritance의 polymorphic discriminator는 category_device이며, type_device가 아니다.

app/models/device.py:65-66
  __mapper_args__ = {
      "polymorphic_on": category_device,   # 진짜 discriminator (이미 안전)
  }

(a) category_device — ORM 다형성을 결정하는 진짜 discriminator. Phase 9에서 이미 불변 처리되어 안전. 추가 차단 불필요.

(b) type_device — EnumDeviceType 19종을 담는 보조 필드. ORM 무결성과 무관하므로 polymorphic 관점의 "절대 불변" 논리가 적용되지 않음.

(c) 1종 고정 카테고리 — 변경 의미 자체가 없음 → 차단 권고: Controller / Camera / Speaker / Enclosure / Lamp 5종은 카테고리당 type_device가 1개로 고정되어 있어, 변경하면 비즈니스적으로 무효 상태가 됨.

(d) Sensor 예외 — 변경 허용 유지: Sensor는 Fence / Multi / SmartCompound / SmartSensor 등 14종이 같은 카테고리 내에 공존하며, 운영 중 센서 모듈 교체·재구성 시 type_device 변경이 정상 운영 케이스. 차단하면 현장 업무가 막힘.

원칙 5. 권한 분리 (RBAC Separation)
role/group_id/permissions 등 권한 상승 가능 필드는 일반 *Update 스키마에서 제거. 전용 admin 엔드포인트 + audit log 강제 + before/after JSONB 스냅샷.
예시: user_groups.permissions (P0, 차단 필요), users.role via PUT /me
원칙 6. 감사 로그 부인방지 (Non-Repudiation)
audit_logs / config_change_logs / user_login_logs는 router-level GET-only를 넘어 DB-level UPDATE/DELETE 차단 필수. PostgreSQL TRIGGER 또는 REVOKE 권한. router 차단만으로 불충분.
예시: 3 테이블 모두 router GET-only ✅ / DB-level은 차단 부재 ❌

Sensor 예외 정책 (type_device 변경 허용)

원칙적으로 type_device는 디바이스 정체성을 결정하는 고정 식별자이므로 PUT/PATCH 시 변경이 차단된다. 단, Sensor 한 종에 한해 물리 센서 모듈 교체·재배선·용도 변경이 빈번한 운영 특성을 반영하여 type_device 변경을 허용한다. 다른 모든 디바이스(Controller / Camera / Speaker / Enclosure / Lamp)는 기존과 동일하게 차단된다.

디바이스별 type_device 변경 정책 매트릭스
Device type_device 변경 정책 DB 실측 type_device 종류 수 운영 시나리오 예시
Controller 차단 1종 (controller 단일) 컨트롤러는 1:1 고정 매핑이므로 종류 변경 자체가 발생하지 않음.
Sensor 허용 (예외) enum 정의 14종 / 시드 2종 등록 현장 센서 모듈을 PIR → 마이크로웨이브로 교체, 또는 미사용 채널을 신규 센서 타입으로 재할당하는 경우.
Camera 차단 1종 (camera 단일) NVR/IP 카메라는 모델 교체 시 신규 디바이스로 재등록해야 하며, 종류 변경 불가.
Speaker 차단 1종 (speaker 단일) 방송용 스피커는 단일 종류로 운영되며 타 디바이스로의 전환이 없음.
Enclosure 차단 1종 (enclosure 단일) 함체는 물리적 외함 단위이며 타 타입으로 변경되는 운영 케이스 없음.
Lamp 차단 1종 (lamp 단일) 경광등은 단일 타입으로 고정 운영되며 종류 변경 발생하지 않음.

주의: Sensor의 type_device 변경은 ConfigChangeLog에 before/after로 자동 기록되며, 매핑된 EventMapping·CategoryEvent의 호환성 검증을 통과해야만 커밋된다.

10.1 차장님 제안 — 두 축 분리 구조

현행 명세는 category_device(7종: Controller/Sensor/Camera/Speaker/Enclosure/Lamp/기타)와 type_device(19종 EnumDeviceType, Sensor 14종 + 기타 5종 혼재)가 동일 평면에서 충돌하고 있습니다.
차장님 제안은 두 축을 명확히 분리합니다.

축 역할 값 (개수) 적용 대상
category_device 장비 대분류 (polymorphic discriminator) Controller, Sensor, Camera, Speaker, Enclosure, Lamp, 기타 (7종) devices 공통 필드 (그대로 유지)
sensor_type 신설 Sensor 한정 세부 타입 Fence, Multi, SmartCompound, SmartSensor 등 (14종) sensors 테이블에만 추가
type_device 폐기 (혼재된 EnumDeviceType) 19종 → 폐기 또는 deprecated devices에서 제거 또는 nullable

10.2 Before / After 비교

Before — 현행 (v4.9까지 유지)

class Device(Base):
    __tablename__ = "devices"
    id_device       = Column(BigInteger, primary_key=True)
    category_device = Column(Enum(EnumCategoryDevice))  # 7종
    type_device     = Column(Enum(EnumDeviceType))      # 19종 (Sensor 14 + 기타 5 혼재)
    # ...

class Sensor(Device):
    __tablename__ = "sensors"
    id_sensor = Column(BigInteger, primary_key=True)
    # sensor_type 없음 — devices.type_device 사용

After — 차장님 제안 (v5.0)

class EnumSensorType(str, Enum):
    Fence          = "Fence"
    Multi          = "Multi"
    SmartCompound  = "SmartCompound"
    SmartSensor    = "SmartSensor"
    # ... 총 14종

class Device(Base):
    __tablename__ = "devices"
    id_device       = Column(BigInteger, primary_key=True)
    category_device = Column(Enum(EnumCategoryDevice))  # 7종 — discriminator
    # type_device 제거 (또는 nullable + deprecated)

class Sensor(Device):
    __tablename__ = "sensors"
    id_sensor   = Column(BigInteger, primary_key=True)
    sensor_type = Column(Enum(EnumSensorType), nullable=False)  # 신설 14종

10.4 권고 사항

  1. v4.9는 현행 구조 유지 — type_device 19종 명세 정합화만 수행 (외부 영향 없음).
